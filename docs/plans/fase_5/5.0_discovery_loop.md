# Fase 5: Discovery Loop (LLM)

> Spec funcional: `docs/plans/fase_5/5.spec.md`
> Este plan implementa los requisitos definidos en la spec anterior.
> Tareas atómicas (>10 pasos): `docs/plans/fase_5/5.tasks.md`

## Objetivo

Un subcomando `discover` que, con una meta en lenguaje natural y una URL de entrada, recorre la UI viva con el bucle `observe -> decide -> act` usando el LLM local, pasa **todas** sus acciones por la política de Fase 4 y, al alcanzar la meta, emite un artefacto válido de Fase 3 más log JSONL y evidencia en `evidence/`. CI totalmente con fakes (sin Ollama ni Chrome).

## Notas / Decisiones técnicas

1. **Detección de meta (`goal_reached`)**: juicio del propio LLM con JSON estricto `{"goal_reached": bool, "reason": str}` tras cada acto exitoso — no hay checkpoint programático confiable en una UI desconocida. Con el fake LLM es determinista; el `reason` alimenta el `checkpoint` del artefacto.
2. **Snapshot interno vs prompt**: `ObservedElement` interno guarda además los **candidatos de locator** (id -> css -> role -> text -> xpath, en orden de fiabilidad) para poder compilar el artefacto; el prompt solo recibe los campos del contrato de la spec (nada interno se filtra al modelo).
3. **URL para `enforce`**: `navigate` evalúa la URL **objetivo** (`value`); el resto de acciones evalúan `current_url` (así `click` en una página `*/execute` dispara `confirm`).
4. **Exit codes**: 0 = `goal_reached`; 10 `blocked`, 11 `needs_approval`, 12 `max_steps`, 13 `timeout`, 14 `dead_end`, 15 `llm_error`; 2 = usage de argparse (estándar).
5. **Escritura incremental**: `safe_write_text` scribe ficheros completos; el JSONL se appendea línea a línea con `redact_text` antes de cada append (misma fuente de redacción, sin duplicar la lógica).
6. **Historial acotado al prompt**: últimos N (p. ej. 5) `(action, reason, outcome)` para dar contexto sin explotar el contexto del modelo.
7. **Parametrización de artefacto**: cada valor `type`/`select` se registra como input con nombre derivado del `name`/label del elemento (slug) o `step{N}_value` de fallback; los `extract` reciben `output_key` automático (`output{N}`) declarado en `output_schema`.
8. **Checkpoint del artefacto**: se deriva del estado final — locators del elemento relevante de la última interacción/meta + `text_present`/`visible` con el `reason` del juicio; si el juicio aporta texto estable se usa literal, si no se usa `url_contains` de la URL final (siempre presente en el contrato Fase 3).
9. **Sin dependencias nuevas**: `argparse` y `json` de stdlib; `ollama` y `python-dotenv` ya declarados. `load_dotenv()` solo en la capa CLI.
10. **CI**: Selenium/Chrome jamás se instancian en tests (driver falso); un test estático verifica que ningún fichero de `discovery/` contiene `time.sleep(`.
11. **Corrida real (Paso 13)**: `uv run python -m proxy_app.app` + Ollama con `qwen2.5-coder:7b` + `uv run computer-use-automation-system discover --goal "..." --entry http://127.0.0.1:5000/`; validar artefacto con `Artifact(**json.load(...))` y copiar log+artefacto a `evidence/`. Requiere confirmación/colaboración del operador (paso manual).

## Correctivos

- **fix-1** (`docs/plans/fixes/fix-1_observe_script_campos_faltantes.md`, aplicado durante Fase 9/T13): `OBSERVE_SCRIPT` no exportaba `id`/`name_attr`/`classes`/`text`/`label` que `build_snapshot` lee — todos los locators degradaban a `input`, el clic de submit resolvía al primer input (campo de texto) y el loop terminaba en `dead_end`. Corregido exportando los 5 campos (`label` = aria-label || innerText || value).
- **fix-2** (`docs/plans/fixes/fix-2_resumen_discovery_log.md`, aplicado durante Fase 9): `write_summary()` solo imprimía el evento de resumen en stdout; el CA 1.3 de Fase 9 exige el resumen en el JSONL. Ahora el resumen se persiste en `log_path` con la misma capa de redacción (stdout intacto).
- **fix-3** (`docs/plans/fixes/fix-3_locators_tag_desnudo.md`, aplicado durante Fase 9): `_build_locators` aceptaba css de tag desnudo (`css: a`, `css: input`) como locator primario — sin atributos no discrimina nada y resolvía al primer elemento de la página (mismo modo de fallo que fix-1 en el submit). Ahora se omite cuando no puede discriminar; tests en `test_discovery_observe.py`.
