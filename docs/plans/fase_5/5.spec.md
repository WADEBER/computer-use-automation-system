# Spec Fase 5: Discovery Loop (LLM)

> Especificación funcional — QUÉ construir y POR QUÉ.
> El CÓMO se define en el plan de fase (5.0_discovery_loop.md).
> Los criterios de aceptación se verifican con `/7-verificar` al terminar la fase.

---

## Problema y objetivo

**Problema**: todavía no existe ninguna manera de *crear* una automatización sin programarla a mano paso a paso. El conocimiento de cómo usar la consola MemberServ (dónde buscar, qué campo rellenar, qué botón pulsar) solo vive en la cabeza de quien escribe el código. Sin un discovery autónomo, el artefacto tipado de la Fase 3 no tiene productor y el replay de la Fase 6 no tendrá nada que reejecutar.

**Objetivo**: un subcomando `discover` que, recibiendo una **meta en lenguaje natural** y una URL de entrada, recorra la UI viva con el bucle `observe -> decide -> act` usando el LLM local (`qwen2.5-coder:7b`), pasando **todas** sus acciones por la política de la Fase 4, y que al alcanzar la meta emita un **artefacto válido de Fase 3** más un log estructurado y su evidencia en `evidence/`. El éxito se ve cuando una corrida real completa contra `proxy_app` produce ese artefacto, y los tests de CI lo demuestran con fakes sin necesitar ni Ollama ni Chrome.

## Historias de usuario

### HU-1: El operador lanza un discovery desde la CLI sin escribir código
**Como** operador/desarrollador del sistema,
**quiero** un subcomando `discover` con meta en lenguaje natural y URL de entrada,
**para** generar una capacidad nueva ejecutando un solo comando.

**Criterios de aceptación:**
- [x] `uv run computer-use-automation-system discover --goal "<meta>" --entry http://127.0.0.1:5000/` lanza una corrida completa (CLI con `argparse` de la stdlib — sin dependencias nuevas).
- [x] `--goal` (no vacío) y `--entry` (http/https) son obligatorios; el uso incorrecto termina con el error de usage de argparse y código de salida 2.
- [x] Opcionales con defaults razonables: `--max-steps` (> 0), `--artifact-out` y `--log-out` (bajo `evidence/` por defecto).
- [x] Código de salida 0 **solo** cuando el status final es `goal_reached`; cualquier otro status (`max_steps`, `timeout`, `dead_end`, `blocked`, `needs_approval`, `llm_error`) sale con código distinto de 0 e imprime el status.
- [x] Cada step emite por stdout una línea JSON con las claves del contrato de log (ver Contratos), no un print libre.

### HU-2: El bucle observe -> decide -> act avanza solo hasta la meta (o se detiene limpio)
**Como** operador del sistema,
**quiero** un bucle autónomo con stopping conditions y anti-bucle,
**para** que la corrida termine siempre en un estado definido, nunca en un loop infinito.

**Criterios de aceptación:**
- [x] **Observe**: snapshot limpio del DOM (elementos interactivos con `ref`, `tag`, `role`, nombre/label, valor, `href`, texto) sin scripts, estilos ni ruido — **nunca** screenshots (el modelo es solo texto).
- [x] El snapshot se serializa como texto estructurado y se trunca de forma determinista al límite `max_snapshot_chars` (defensa de contexto).
- [x] **Decide**: prompt estructurado (meta + snapshot + historial acotado) con salida JSON estricta y tipada (`LLMAction`): acción perteneciente a `ActionType` + `reason` obligatorio.
- [x] Decisión inválida (JSON malformado, acción desconocida, `element_ref` inexistente, `value` ausente donde hace falta) -> reintento con feedback hasta 2 veces; si persiste -> status `llm_error` (fail closed, sin excepción cruda).
- [x] **Act**: acciones Selenium reales (`click`, `type`, `navigate`, `select`, `extract`) con `WebDriverWait` explícito; `time.sleep()` prohibido.
- [x] Stopping conditions completas: `goal_reached` (meta cumplida), `max_steps`, `timeout` (límite global), `dead_end` (sin progreso).
- [x] Anti-bucle: firma/hash del snapshot; si la misma firma se repite `repeat_threshold` veces consecutivas -> `dead_end`.
- [x] Cada log lleva el step actual y el máximo (`step_index` / `max_steps`) para poder auditar la corrida.
- [x] Con el mismo fake LLM y el mismo estado inicial, la secuencia de pasos es determinista (test).

### HU-3: Ninguna acción se ejecuta sin pasar por la política de Fase 4
**Como** responsable de seguridad,
**quiero** que el runner llame a `enforce()` antes de cada acción,
**para** que el discovery herede el perímetro y los veredictos ya construidos.

**Criterios de aceptación:**
- [x] `enforce()` se invoca antes de **cada** acción `act`; su `Decision` se registra en el `StepRecord` correspondiente.
- [x] Veredicto `block` -> la corrida termina con status `blocked` y la acción **jamás** se ejecuta (el driver no recibe la llamada).
- [x] Veredicto `confirm` (p. ej. rutas `*/execute`) -> la corrida termina con status `needs_approval` sin ejecutar la acción (el handoff humano real llega en Fase 8).
- [x] Veredicto `flag` -> la acción se ejecuta y el veredicto (con su `reason`) queda registrado en la traza.
- [x] El log JSONL y el artefacto se escriben a través de la redacción de Fase 4 (`RedactionFilter` / `safe_write_text`): ni nombres, ni saldos, ni importes, ni secretos en claro.
- [x] Test negativo: un fake LLM que decide navegar a un dominio externo produce `blocked` y no hay llamada de acción sobre el driver.

### HU-4: La corrida deja un artefacto Fase 3 válido y su evidencia
**Como** reviewer humano del sistema,
**quiero** que la meta alcanzada se materialice en el mismo contrato tipado de Fase 3,
**para** que el artefacto sea entendible y reutilizable por el replay sin tocar código.

**Criterios de aceptación:**
- [x] Si (y solo si) el status es `goal_reached`, se emite un artefacto que **valida** contra `Artifact` de Fase 3 (`Artifact(**raw)` sin error) — test automatizado.
- [x] El artefacto refleja lo ejecutado: steps ordenados, con los locators que realmente funcionaron (orden de fallback observado) y el `checkpoint` de la meta.
- [x] Los valores de steps `type`/`select` quedan parametrizados como `{{input.*}}` con las claves declaradas en `input_schema.properties` (invariante Fase 3).
- [x] Log JSONL con un objeto por step y claves fijas: `step_index`, `action`, `element_ref`, `value_preview`, `reason`, `policy_decision`, `outcome`, `snapshot_hash`, `elapsed_ms`.
- [x] La evidencia (log + artefacto + resumen de corrida) se escribe bajo `evidence/` (o `--artifact-out`/`--log-out` explícitos); no se escriben ficheros fuera de esas rutas.
- [x] Si el status no es `goal_reached` **no** se emite artefacto (solo log con el status final) — nada incompleto se cuela en el repositorio de artefactos.
- [x] El contenido escrito no contiene PII ni secretos en claro (test sobre los ficheros generados con datos semilla del proxy).

### HU-5: El discovery es testeable en CI sin Ollama ni Chrome
**Como** mantenedor del repo,
**quiero** el runner con dependencias inyectadas (LLM, driver, política),
**para** que la suite pase en GitHub Actions (sin red ni navegador).

**Criterios de aceptación:**
- [x] El runner acepta inyectar el cliente LLM, el driver y la política; los defaults reales (Ollama + Selenium) solo se usan en la CLI.
- [x] Fakes en tests: LLM con respuestas pregrabadas y driver con DOM falso; ningún test de CI abre red, Ollama ni Chrome.
- [x] Cobertura de estados: `goal_reached` (con artefacto válido), `blocked`, `needs_approval`, `dead_end`, `llm_error` y `max_steps` — al menos un test por status.
- [ ] La corrida real con Ollama + Chrome queda como **evidencia manual** de cierre (fuera de CI), ejecutada al terminar la fase.

## Contratos de datos

### `DiscoveryConfig` (entrada del runner)

| Campo | Tipo | Restricciones |
|-------|------|---------------|
| goal | str | no vacío; meta en lenguaje natural |
| entry_url | str | `http://` o `https://` |
| max_steps | int | > 0, default 15 |
| step_timeout_ms | int | > 0, default 15000 (espera `WebDriverWait` por step) |
| total_timeout_ms | int | > 0, default 300000 (timeout global de corrida) |
| repeat_threshold | int | >= 2, default 3 (veces iguales antes de `dead_end`) |
| max_snapshot_chars | int | > 0, default 8000 (truncado del snapshot) |
| max_llm_retries | int | >= 0, default 2 (reintentos de Decisión inválida) |
| artifact_out | Path | default bajo `evidence/` |
| log_out | Path | default bajo `evidence/` |
| ollama_base_url | str | default desde `OLLAMA_BASE_URL` |
| ollama_model | str | default desde `OLLAMA_MODEL` (`qwen2.5-coder:7b`) |

**Invariantes:**
- La política (`config/policy.json`) **no** es un campo editable de la config: se carga desde su fichero único (Fase 4); el runner no la modifica.
- La CLI traduce flags a `DiscoveryConfig`; la librería no lee `sys.argv`.

### Snapshot de observe (entrada al prompt)

Elemento interactivos del DOM serializado a JSON compacto de texto:

| Campo | Tipo | Restricciones |
|-------|------|---------------|
| ref | int | índice estable 1..N dentro del step; único por snapshot |
| tag | str | nombre de la etiqueta HTML |
| role | str | `aria-role` o derivada del tag (`button`, `link`, `input`...) |
| name | str | label/aria-label/texto visible, recortado a 80 chars |
| value | str | atributo `value` si existe, recortado a 120 chars |
| href | str \| null | si el elemento es enlace |
| text | str \| null | texto visible, recortado a 120 chars |

**Invariantes:**
- Sin `script`, `style`, `img` ni atributos de presentación en el snapshot.
- El texto completo del snapshot respeta `max_snapshot_chars` (truncado determinista, marcado como truncado en el prompt).
- `ref` solo es válido dentro del step en que se emitió (el siguiente observe lo re-emite).

### `LLMAction` (salida tipada del modelo)

| Campo | Tipo | Restricciones |
|-------|------|---------------|
| action | ActionType | `navigate` / `click` / `type` / `extract` / `select` (enum Fase 3) |
| element_ref | int \| null | obligatorio para `click`/`type`/`extract`/`select`; `null` para `navigate` |
| value | str \| null | obligatorio (no vacío) para `type`/`select` (texto) y `navigate` (URL http(s)); `null` para `click`/`extract` |
| reason | str | no vacío — por qué el modelo elige esta acción (auditoría) |

**Invariantes:**
- JSON estricto (`extra="forbid"`): campos extra = decisión inválida (reintento).
- `element_ref` debe existir en el snapshot del step o la decisión es inválida.
- La salida del modelo se valida con Pydantic **antes** de tocar el driver (dos modelos fallan distintos: `llm_error` vs fallo de ejecución).

### `StepRecord` (una línea del log JSONL)

| Campo | Tipo | Restricciones |
|-------|------|---------------|
| step_index | int | 1..max_steps, secuencial |
| action | ActionType | acción decidida |
| element_ref | int \| null | ref usado, si aplica |
| value_preview | str \| null | valor **ya redactado** (o recortado), nunca PII cruda |
| reason | str | razón del LLM, truncada |
| policy_decision | object \| null | `{decision, reason}` del `enforce` (si hubo evaluación) |
| outcome | str | qué pasó al actuar (`ok`, `element_not_found`, `stale`, ...) |
| snapshot_hash | str | firma del observe (anti-bucle) |
| elapsed_ms | int | duración del step |
| step_index / max_steps | int | progreso visible en cada línea |

### `DiscoveryResult` (resultado de la corrida)

| Campo | Tipo | Restricciones |
|-------|------|---------------|
| status | enum | `goal_reached` \| `max_steps` \| `timeout` \| `dead_end` \| `blocked` \| `needs_approval` \| `llm_error` |
| steps | list[StepRecord] | 0..max_steps, en orden |
| artifact | Artifact \| null | no nulo **solo si** `status == goal_reached` |
| artifact_path | Path \| null | ruta escrita, si hubo artefacto |
| log_path | Path | ruta del JSONL (siempre, salvo error de config) |

**Invariantes:**
- `artifact != null` si y solo si `status == goal_reached` (y el artefacto valida contra Fase 3 antes de escribirse).
- `status == blocked` => la última decisión **no** se ejecutó jamás.
- `status == needs_approval` => ninguna acción `confirm` se ejecutó.
- Cada `StepRecord.policy_decision` coincide con lo que `enforce` devolvió para ese step.

## Restricciones

- **LLM local**: Ollama `qwen2.5-coder:7b` (`OLLAMA_BASE_URL`, `OLLAMA_MODEL`); modelo **solo texto** — prohibido cualquier input visual (screenshots) al modelo.
- **Navegador**: Selenium + Chrome; exclusivamente `WebDriverWait` (sin `time.sleep()`).
- **Sin dependencias nuevas**: `argparse` (stdlib) para la CLI; el cliente `ollama` (0.6.x) ya está declarado en `pyproject.toml`.
- **Seguridad**: la política de Fase 4 (`config/policy.json`) es la única fuente de permisos; el discovery solo la *lee*. Toda escritura pasa por la redacción de Fase 4.
- **CI**: GitHub Actions sin Ollama, sin Chrome y sin red — todos los tests con fakes inyectados.
- **Convenciones**: inglés en código, logs y artefactos; sin Unicode especial en `print()`/logging de Python; type hints en todas las funciones nuevas; ruff línea 100.
- **Corrida real**: requiere `proxy_app` levantada en local + Ollama sirviendo el modelo; es evidencia de cierre, no test de CI.

---

## Anti-objetivos (lo que esta fase NO hace)

- NO replay determinista del artefacto (Fase 6).
- NO taxonomía de errores de negocio, reintentos por diálogo ni clasificación de fallos (Fase 7).
- NO handoff humano en la sesión viva: `confirm` **termina** el run, nadie aprueba en vivo todavía (Fase 8).
- NO screenshots ni ningún input visual al LLM (modelo de texto).
- NO tests de CI contra Ollama o Chrome reales.
- NO modificar `src/proxy_app/`, `config/policy.json` ni los modelos de Fase 3 (solo consumirlos).
- NO discovery multi-goal, batch ni programación de corridas.
- NO `REPORT.md` ni evidencia final del proyecto (Fase 9) — solo la evidencia inicial de esta fase.
- NO fine-tuning ni entrenamiento de modelos: solo prompts + JSON estricto con reintento.
