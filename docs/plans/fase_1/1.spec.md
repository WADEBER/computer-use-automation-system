## Problema y objetivo

**Problema**: El repositorio del take-home no tiene una base de desarrollo reproducible. Sin estructura de proyecto, dependencias declaradas, tooling de calidad ni CI, cada colaborador (y el agente) tendría que reconstruir el entorno a mano, con riesgo de divergencia, secretos mal manejados y entregables no verificables.

**Objetivo**: Un clone del repo permite a cualquier desarrollador o agente pasar de cero a `pytest` y `ruff` en verde con `uv sync`, usando Python 3.11, estructura `src/`+`tests/` en inglés, configuración de entorno sin secretos y un CI que valide lint y tests en cada push.

## Restricciones

- **Python 3.11**: `requires-python = ">=3.11"` y CI fijado a 3.11 (no subir sin actualizar el workflow).
- **Package manager**: uv exclusivamente — no poetry/pipenv/make.
- **Sin Docker**: decisión explícita del usuario en el scaffold; no añadirlo en esta fase.
- **Idioma**: todo código, docs y entregables en inglés (ver `CLAUDE.md`).
- **Sin secretos**: `.env` nunca se commitea; solo `.env.example`.
- **Sin Unicode especial** en `print()`/logging Python (`[OK]`, `->` en lugar de flechas/emojis).
