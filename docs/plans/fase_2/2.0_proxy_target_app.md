# Fase 2: Proxy Target App

> Spec funcional: `docs/plans/fase_2/2.spec.md`
> Este plan implementa los requisitos definidos en la spec anterior.

## Objetivo

App Flask local en `src/proxy_app/` que simula un back-office bancario legado con flujo **member search -> detail -> loan disbursement con confirmación**, seed determinista en memoria, escenarios de excepción (not found, validación) y marcado realista sin `data-testid` — target automatizable para las Fases 5-8.

## Notas / Decisiones técnicas

- **Contrato de confirmación en dos POSTs** (spec): `POST .../disburse` valida y renderiza confirmación (no ejecuta); `POST .../disburse/execute` ejecuta. La "expiración" del resumen se modela re-validando en execute (sin sesión de servidor) — suficiente y determinista.
- **`disbursement_no`**: contador correlativo en memoria de la app (`DISB-0001`...), se resetea al reiniciar — coherente con seed in-memory.
- **Templates en `src/proxy_app/templates/`**: ruta por defecto de Flask relativa al paquete; sin config extra.
- **Marcado legado a propósito**: tablas, `name`-based forms, ids heredados; prohibido añadir `data-testid` (test Paso 8 lo bloquea).
- **Tests planos con prefijo `proxy_`**: sigue la convención existente (`test_proxy_app_smoke.py`); el espejo estricto `tests/proxy_app/` queda para si el test suite crece.
- **Sin JS obligatorio**: la confirmación es página intermedia con aspecto de modal (div overlay) — el flujo funciona sin ejecutar JavaScript (el discovery de Fase 5 no debe depender de JS).
- **Seed mínimo**: 3 miembros (uno con nombre buscable fácil, balances distintos, credit_limit variable) — suficiente para not-found y límites de crédito.
- Seguridad mantenerla: sin inputs reflejados sin escapar (usar `render_template` con Jinja — escaping por defecto), bandit debe seguir en verde.
