## 1. Executive Summary

The Phase 4 policy engine fails closed on the obvious cases (external origins, disallowed routes/action types) and the redaction layer is config-driven with validated, compile-checked regexes and no hardcoded credentials. However, the origin check treats any URL without `://` as same-origin, so a scheme-relative URL (`//host/path`) passes the perimeter and would navigate the automated browser off-origin; URL paths are also checked without normalization, so dot-segment escapes (`/members/../...`) pass the route allowlist. Two lower-severity issues cover log newline injection and the lack of path containment in the file writer. No Critical findings under the reviewed scope; the single High must be resolved or explicitly deferred before Phase 4 can close.

## 3. Findings

### 3.1 [SEC-001] Perimeter bypass: scheme-relative URLs and non-normalized paths — **High**

- **File:** [src/computer_use_automation_system/safety/policy.py:31](src/computer_use_automation_system/safety/policy.py#L31) (`_origin_allowed`) and [policy.py:50](src/computer_use_automation_system/safety/policy.py#L50) (`evaluate`)
- **CWE:** CWE-346 (Origin Validation Error); path half: CWE-20 (Improper Input Validation)
- **OWASP:** A01 — Broken Access Control
- **Confidence:** Confirmed (logic verified by code reading; PoC not executed, per audit rules)
- **Tool:** manual review

**Description**

`_origin_allowed` returns `True` for every URL that does not contain `://`, treating it as same-origin. A scheme-relative URL such as `//evil.example/members` contains no `://`, so it skips the origin check entirely; `urlsplit("//evil.example/members")` yields `path == "/members"`, which is allowlisted, so `evaluate` returns `ALLOW`. The browser interprets `//evil.example/members` as protocol-relative and navigates to `http://evil.example/members` — outside the configured perimeter. Separately, the route check runs on the raw (un-decoded, un-normalized) path, so dot-segments pass the allowlist while the browser resolves them elsewhere.

**Vulnerable code**

```python
# src/computer_use_automation_system/safety/policy.py:31
def _origin_allowed(url: str, allowed_origins: list[str]) -> bool:
    if "://" not in url:
        return True          # "//evil.example/members" lands here -> trusted
    return any(url.startswith(origin) for origin in allowed_origins)

# src/computer_use_automation_system/safety/policy.py:50
path = urlsplit(url).path or "/"   # raw: "/members/../admin" passes "/members" allowlist
```

**Impact**

The perimeter is the core security promise of Phase 4. An artifact URL (produced by LLM discovery or edited on disk) can point the automated browser at an attacker-chosen origin while `evaluate`/`enforce` report `ALLOW`. Combined with a subsequent `type` step, member PII or form data could be entered into a lookalike page (exfiltration). The path half lets navigation escape `allowed_routes` within the same origin (current proxy app has no sensitive off-allowlist routes, but the control itself is broken and replay will grow).

**Reproduction / PoC sketch** (do NOT run)

> 1. Artifact step `{"action_type": "navigate", "url": "//evil.example/members"}` -> `evaluate(policy, "navigate", "//evil.example/members")` returns `DecisionKind.ALLOW` (expected: BLOCK, origin `evil.example` not in `allowed_origins`). Selenium navigating to it resolves to `http://evil.example/members`.
> 2. Step `{"action_type": "navigate", "url": "http://127.0.0.1:5000/members/../anything"}` -> route check sees `"/members/../anything"`, `startswith("/members/")` is true -> ALLOW, browser resolves to `http://127.0.0.1:5000/anything`.
> 3. Encoded variant `"/members/%2e%2e/anything"` behaves the same because `urlsplit` does not decode and no `unquote` is applied.

**Remediation**

```python
# src/computer_use_automation_system/safety/policy.py — fixed
import posixpath
from urllib.parse import unquote, urlsplit

def _origin_allowed(url: str, allowed_origins: list[str]) -> bool:
    parts = urlsplit(url)
    if not parts.scheme and not parts.netloc:
        return True                      # pure relative path -> same origin
    if not parts.scheme or not parts.netloc:
        return False                     # scheme-relative (//host/...) or malformed
    origin = f"{parts.scheme}://{parts.netloc}"
    return origin in {o.rstrip("/") for o in allowed_origins}

# in evaluate(), replace line 50:
parts = urlsplit(url)
path = posixpath.normpath(unquote(parts.path)) if parts.path else "/"
# normpath collapses "/members/../admin" -> "/admin" and "%2e%2e" after unquote,
# so the route allowlist is checked against the same path the browser will request.
# Comparing parsed origins (not startswith) also removes the trailing-slash format
# dependency of the current config check.
```

Add regression tests: scheme-relative external URL -> BLOCK; dot-segment and `%2e%2e` paths checked against the *normalized* path; origin without trailing slash in config behaves identically.

### 3.2 [SEC-002] Log injection: CRLF not neutralized by RedactionFilter — **Low**

- **File:** [src/computer_use_automation_system/safety/redaction.py:24](src/computer_use_automation_system/safety/redaction.py#L24)
- **CWE:** CWE-117 (Improper Output Encoding for Logs)
- **OWASP:** A09 — Security Logging and Monitoring Failures
- **Confidence:** Confirmed
- **Tool:** manual review

**Description**

`RedactionFilter.filter` redacts the formatted message but leaves CR/LF characters intact. Any attacker-influenced string that reaches logging (e.g. text extracted from a page, form input echoed into an error message) can embed newlines and forge additional log lines.

**Vulnerable code**

```python
# src/computer_use_automation_system/safety/redaction.py:24
def filter(self, record: logging.LogRecord) -> bool:
    record.msg = redact_text(record.getMessage(), self._config)
    record.args = None
    return True   # no newline/control-char handling
```

**Impact**

The redacted logs are the audit trail of the system (who decided what, when). A forged `policy allow: ...` line could mislead an auditor or an automated log parser. No direct data access; integrity of evidence only.

**Reproduction / PoC sketch** (do NOT run)

> `logger.info("extract result: %s", "ok\r\npolicy allow: execute approved")` produces two log lines; the second is a fabricated verdict.

**Remediation**

```python
# src/computer_use_automation_system/safety/redaction.py:24 — fixed
def filter(self, record: logging.LogRecord) -> bool:
    message = redact_text(record.getMessage(), self._config)
    record.msg = message.replace("\r", "\\r").replace("\n", "\\n")
    record.args = None
    return True
```

Escaping (not stripping) preserves the information while keeping the record one physical line. Apply the same escaping inside `safe_write_text` if evidence files are ever line-oriented (JSONL, CSV).

**References**

- [CWE-117](https://cwe.mitre.org/data/definitions/117.html)

### 3.3 [SEC-003] `safe_write_text` performs no path containment check — **Low**

- **File:** [src/computer_use_automation_system/safety/redaction.py:65](src/computer_use_automation_system/safety/redaction.py#L65)
- **CWE:** CWE-22 (Path Traversal)
- **OWASP:** A01 — Broken Access Control
- **Confidence:** Possible (no untrusted caller exists yet; becomes relevant when the evidence writer is wired in Phase 5+)
- **Tool:** manual review

**Description**

`safe_write_text(path, ...)` writes to any caller-supplied path, creating parent directories, with no containment to an approved base (e.g. `evidence/`). Today only tests call it with `tmp_path`; the risk materializes when artifact-specified or LLM-suggested output paths flow in.

**Vulnerable code**

```python
# src/computer_use_automation_system/safety/redaction.py:75
target = Path(path)
target.parent.mkdir(parents=True, exist_ok=True)
target.write_text(redact_text(text, redaction), encoding="utf-8")
```

**Impact**

Arbitrary file write (overwrite of config, `.env`, or other project files) if an untrusted path ever reaches the function.

**Reproduction / PoC sketch** (do NOT run)

> `safe_write_text("../../config/policy.json", "...")` would overwrite the policy file itself with redacted content — i.e. the guardrail configuration.

**Remediation**

```python
# src/computer_use_automation_system/safety/redaction.py:65 — fixed
def safe_write_text(
    path: str | Path,
    text: str,
    config: RedactionConfig | None = None,
    *,
    base_dir: str | Path | None = None,
) -> None:
    from computer_use_automation_system.safety.policy import load_policy
    redaction = config if config is not None else load_policy().redaction
    target = Path(path)
    if base_dir is not None:
        base = Path(base_dir).resolve()
        target = (base / target).resolve() if not target.is_absolute() else target.resolve()
        if base != target and base not in target.parents:
            raise PermissionError(f"write path escapes base_dir: {target}")
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_text(redact_text(text, redaction), encoding="utf-8")
```

When the evidence writer lands (Fase 5), make `base_dir=evidence/` mandatory at that call site.
