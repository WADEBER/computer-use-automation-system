No critical findings were identified under the reviewed scope, and no High or Medium issues remain: the interactive path correctly constrains stdin to a whitelist, keeps the browser session closed through `finally`, restores the control state fail-closed, and passes every free-text field through redaction before it reaches a handoff record. ## 3. Findings

### 3.1 [SEC-801] Policy rule reason reaches interactive prints with CRLF intact — **Low**

- **File:** [src/computer_use_automation_system/safety/models.py:34](src/computer_use_automation_system/safety/models.py#L34) (`PolicyRule.reason`, no control-char validation) — flows through [src/computer_use_automation_system/safety/policy.py:98](src/computer_use_automation_system/safety/policy.py#L98) and [src/computer_use_automation_system/replay/engine.py:194](src/computer_use_automation_system/replay/engine.py#L194), printed at [src/computer_use_automation_system/cli.py:126](src/computer_use_automation_system/cli.py#L126) (new Phase 8 surface) and [src/computer_use_automation_system/cli.py:209](src/computer_use_automation_system/cli.py#L209) (pre-existing)
- **CWE:** CWE-117 (Improper Output Neutralization for Logs)
- **OWASP:** A09 — Security Logging and Monitoring Failures
- **Confidence:** Confirmed (code path read end to end; `redact_text` preserving `chr(10)` was reproduced in the Phase 7 SEC-002 fix)
- **Tool:** manual review

**Description**

`PolicyRule.reason` accepts any non-empty string. Unlike the failure-taxonomy patterns — which got `_has_control_chars` validation in the Phase 7 SEC-002 fix — the policy reason has no control-character guard. The reason travels unmodified into `Decision.reason`, then into `HandoffRequest.reason`. `redact_text` masks secrets but never strips CR/LF, and the new `PromptOperator` prints it with raw `print()`, which bypasses `RedactionFilter` (the only place CR/LF are neutralized, [src/computer_use_automation_system/safety/redaction.py:26](src/computer_use_automation_system/safety/redaction.py#L26)). An extra newline in a reason therefore becomes a new "line" of attacker-controlled terminal output.

**Vulnerable code**

```python
# src/computer_use_automation_system/safety/models.py:34
    decision: DecisionKind
    reason: str = Field(min_length=1)   # no control-char validation
```

```python
# src/computer_use_automation_system/cli.py:126 (Phase 8, new)
    print(f"reason={request.reason}")   # raw print(), bypasses RedactionFilter
```

**Impact**

An adversary who can modify `config/policy.json` (supply-chain or local tampering) injects forged lines such as a fake `replay success: ...` or a fake `decision [resume|finish|abort]:` prompt into the operator's terminal during `replay --interactive`, or into redirected stdout captured in shared logs. This can mislead an operator watching a live handoff or confuse log parsers. It does not lead to code execution; impact is output forgery and log-injection, hence Low for a local, single-user CLI.

**Reproduction / PoC sketch** (do NOT run)

> Add a rule to `config/policy.json` with `"reason": "needs review\nreplay success: forged-capability v9"`, run `uv run computer-use-automation-system replay ... --interactive`, and reach any handoff pause: the pause summary prints a second, forged `replay success` line below `reason=`.

**Remediation**

```python
# src/computer_use_automation_system/safety/models.py — fixed
from computer_use_automation_system.replay.taxonomy import _has_control_chars  # or duplicate the helper

class PolicyRule(BaseModel):
    match_action_type: ActionType | None = None
    match_url_pattern: str | None = None
    decision: DecisionKind
    reason: str = Field(min_length=1)

    @field_validator("reason")
    @classmethod
    def _reason_must_not_forge_output(cls, value: str) -> str:
        if _has_control_chars(value):
            raise ValueError("reason must not contain control characters")
        return value
```

Defense in depth (neutralize at the print boundary even if a future field skips validation):

```python
# src/computer_use_automation_system/cli.py:126 — fixed (defense in depth)
    print(f"reason={request.reason.replace(chr(13), '\\r').replace(chr(10), '\\n')}")
```

The validator keeps forged reasons out of `config/policy.json` at load time (same pattern the taxonomy already uses, [src/computer_use_automation_system/replay/taxonomy.py:29](src/computer_use_automation_system/replay/taxonomy.py#L29)); the print-boundary replace mirrors `RedactionFilter` so `print()` gets the same hygiene as the logging path.

**References**
- [CWE-117](https://cwe.mitre.org/data/definitions/117.html)
- [OWASP A09:2021 — Security Logging and Monitoring Failures](https://owasp.org/Top10/A09_2021-Security_Logging_and_Monitoring_Failures/)
- Phase 7 report, SEC-002 (same CRLF class, taxonomy patterns): `docs/security/audit-2026-09-28-fase-7.md`

### 3.2 [SEC-802] Replay outputs reach stdout without redaction — **Low**

- **File:** [src/computer_use_automation_system/replay/engine.py:514](src/computer_use_automation_system/replay/engine.py#L514) (raw value stored) and [src/computer_use_automation_system/cli.py:200](src/computer_use_automation_system/cli.py#L200) (raw value printed)
- **CWE:** CWE-532 (Insertion of Sensitive Information into Log)
- **OWASP:** A09 — Security Logging and Monitoring Failures
- **Confidence:** Confirmed (code read; values originate from `discovery/act.py` extraction of live page text)
- **Tool:** manual review

**Description**

`EXTRACT` step results are stored into `ReplayResult.outputs` verbatim (`outputs[step.output_key] = outcome.extracted`) and `_print_replay_result` prints every output with a raw f-string. Extracted values are live page text from the banking target (balances, references, account identifiers), so this violates the project invariant "redact at the write layer". All other terminal text in the replay path is redacted at construction (failure messages at [engine.py:468](src/computer_use_automation_system/replay/engine.py#L468), handoff reasons at [engine.py:194](src/computer_use_automation_system/replay/engine.py#L194)); outputs are the one exception. This is pre-existing Phase 6 code surfaced here because Phase 6 has no mandatory audit and both files were read in full during this review.

**Vulnerable code**

```python
# src/computer_use_automation_system/replay/engine.py:514
        if step.action_type is ActionType.EXTRACT and step.output_key:
            outputs[step.output_key] = outcome.extracted   # raw page text
```

```python
# src/computer_use_automation_system/cli.py:200
            print(f"output {key}={result.outputs[key]}")   # no redact_text
```

**Impact**

When stdout is redirected to a log file (CI, `tee`, scheduler capture), regulated PII extracted from the page is written without passing `redact_text`, while every other line in the same log is redacted. On the operator's own terminal the impact is minimal (the operator can already see the page), which keeps this at Low.

**Reproduction / PoC sketch** (do NOT run)

> Run a replay whose artifact extracts a card-like value (e.g. `4111 1111 1111 1111`) with `replay ... > run.log`; `run.log` contains the raw value while redacted patterns in other lines show `[REDACTED_CARD]`.

**Remediation**

```python
# src/computer_use_automation_system/cli.py — fixed (print-time redaction)
from computer_use_automation_system.safety.redaction import redact_text

def _print_replay_result(result: ReplayResult, redaction: RedactionConfig) -> None:
    ...
    for key in sorted(result.outputs or {}):
        print(f"output {key}={redact_text(str(result.outputs[key]), redaction)}")
```

Pass `policy.redaction` from `_run_replay_command` (policy is already loaded at [cli.py:237](src/computer_use_automation_system/cli.py#L237)). Keep `ReplayResult.outputs` raw: it is the machine-readable deliverable, and the Phase 9 evidence writer will redact at its own write layer via `safe_write_text`.

**References**
- [CWE-532](https://cwe.mitre.org/data/definitions/532.html)
- [OWASP A09:2021](https://owasp.org/Top10/A09_2021-Security_Logging_and_Monitoring_Failures/)

### 3.3 [SEC-803] Interactive command surfaces raw tracebacks on unhandled exceptions — **Low**

- **File:** [src/computer_use_automation_system/cli.py:129](src/computer_use_automation_system/cli.py#L129) (`input()` catches only `EOFError`/`KeyboardInterrupt`), [src/computer_use_automation_system/cli.py:237](src/computer_use_automation_system/cli.py#L237) (`load_policy()` unguarded), [src/computer_use_automation_system/cli.py:261](src/computer_use_automation_system/cli.py#L261) (`main()` has no top-level handler)
- **CWE:** CWE-209 (Generation of Error Message Containing Sensitive Information)
- **OWASP:** A09 — Security Logging and Monitoring Failures (error-output hygiene; approximate mapping)
- **Confidence:** Confirmed (code read)
- **Tool:** manual review

**Description**

`main()` dispatches straight into the command handlers with no top-level exception boundary. Taxonomy config errors are handled gracefully (exit 2 with field names only, [cli.py:217-227](src/computer_use_automation_system/cli.py#L217)), but `load_policy()` failures (`OSError`, `ValidationError`), Selenium errors escaping `_execute_replay`, exceptions raised by a custom `Operator.intervene` implementation, and `UnicodeDecodeError` from `input()` on malformed stdin all propagate to the console as a raw traceback. Phase 8 increases exposure: `--interactive` puts stdin decoding and operator code on the hot path.

**Vulnerable code**

```python
# src/computer_use_automation_system/cli.py:129
        raw = input("decision [resume|finish|abort]: ")   # UnicodeDecodeError not caught

# src/computer_use_automation_system/cli.py:237
    policy = load_policy()   # OSError/ValidationError unguarded (taxonomy is guarded above)

# src/computer_use_automation_system/cli.py:261
def main(argv: list[str] | None = None) -> int:   # no top-level handler
```

**Impact**

Full stack traces (absolute paths, code structure, exception payloads) reach the terminal and any redirected log. With a tampered or missing `config/policy.json` the traceback may include fragments of config content. No code execution; local information disclosure, hence Low. Note the browser session is still closed correctly: `_execute_replay`'s `finally: driver.quit()` runs before the traceback escapes.

**Reproduction / PoC sketch** (do NOT run)

> Rename `config/policy.json` and run `replay ... --interactive`: instead of the clean exit-2 style message used for taxonomy, the CLI dies with a `FileNotFoundError` traceback.

**Remediation**

```python
# src/computer_use_automation_system/cli.py:129 — fixed
        try:
            raw = input("decision [resume|finish|abort]: ")
        except (EOFError, KeyboardInterrupt, UnicodeDecodeError, OSError):
            print("handoff: no input available; aborting")
            return OperatorResponse(decision="abort")
```

```python
# src/computer_use_automation_system/cli.py:237 — fixed (mirror the taxonomy guard at :217)
    try:
        policy = load_policy()
    except OSError as exc:
        print(f"replay: invalid policy config: {exc.strerror or 'read error'}", file=sys.stderr)
        return 2
    except ValidationError as exc:
        fields = ", ".join(".".join(str(p) for p in err["loc"]) for err in exc.errors())
        print(f"replay: invalid policy config (fields: {fields})", file=sys.stderr)
        return 2
```

Optionally wrap the `main()` dispatch with `except KeyboardInterrupt: return 130` so Ctrl+C outside the prompt exits cleanly instead of dumping a traceback. Field names only on `ValidationError` preserves the Phase 7 SEC-001 fix (no config values echoed back).

**References**
- [CWE-209](https://cwe.mitre.org/data/definitions/209.html)
- Phase 7 report, SEC-001 (same class for taxonomy config): `docs/security/audit-2026-09-28-fase-7.md`

### 3.4 [SEC-804] Handoff pause blocks indefinitely with no deadline — **Info**

- **File:** [src/computer_use_automation_system/replay/engine.py:202](src/computer_use_automation_system/replay/engine.py#L202) (`response = op.intervene(request)`)
- **CWE:** CWE-400 (Uncontrolled Resource Consumption)
- **OWASP:** A04 — Insecure Design
- **Confidence:** Confirmed (code read)
- **Tool:** manual review

**Description**

`_pause` blocks on `Operator.intervene` with no timeout. For `PromptOperator` this is intended UX (the human is the deadline), but a programmatic operator implementation (Phase 9+ integrations: webhooks, chat ops) that hangs leaves the replay — and the live Chrome session it owns — suspended forever.

**Impact**

One hung process and one idle browser session per stuck handoff. No amplification, local scope: Info.

**Remediation**

Document the contract on `Operator.intervene` in [src/computer_use_automation_system/replay/handoff.py](src/computer_use_automation_system/replay/handoff.py) ("must return within a bounded time; on timeout the implementation returns `abort`"), and track an optional `handoff_timeout_ms` parameter for `run_replay` in the backlog. `input()` itself cannot be timed out portably in Python, so enforcement belongs to the operator implementation.

### 3.5 [SEC-805] Handoff records carry unbounded snapshot/note/description sizes — **Info**

- **File:** [src/computer_use_automation_system/replay/models.py:117](src/computer_use_automation_system/replay/models.py#L117) (`snapshot`), [src/computer_use_automation_system/replay/models.py:149](src/computer_use_automation_system/replay/models.py#L149) (`resumed_snapshot`), populated at [src/computer_use_automation_system/replay/engine.py:197](src/computer_use_automation_system/replay/engine.py#L197) and [src/computer_use_automation_system/replay/engine.py:215](src/computer_use_automation_system/replay/engine.py#L215)
- **CWE:** CWE-770 (Allocation of Resources Without Limits or Throttling)
- **OWASP:** A05 — Security Misconfiguration
- **Confidence:** Confirmed (code read)
- **Tool:** manual review

**Description**

Every pause stores a full redacted DOM snapshot in `HandoffRequest`, and every resume/finish stores a second snapshot in `HandoffRecord.resumed_snapshot`, with no model-level size cap (`snapshot: list[dict[str, object]]`, `note`/`description` unbounded strings). Today records live only in `ReplayResult.handoff` (in memory); the impact materializes when the Phase 9 evidence writer serializes them.

**Impact**

A large page plus a long operator note can produce multi-megabyte handoff records and evidence JSON files, degrading memory and storage. No integrity impact: Info.

**Remediation**

```python
# src/computer_use_automation_system/replay/models.py — fixed
MAX_SNAPSHOT_ENTRIES = 500

    snapshot: list[dict[str, object]] = Field(max_length=MAX_SNAPSHOT_ENTRIES)
    resumed_snapshot: list[dict[str, object]] | None = Field(default=None, max_length=MAX_SNAPSHOT_ENTRIES)
    note: str | None = Field(default=None, max_length=500)
```

Truncate at capture time in `_snapshot()` (keep the first N entries plus a marker entry) so the cap holds regardless of caller.
